# AGENTS.md

These rules must be followed.

## Branching

Create a disposable branch for each task and never commit directly to `dev` or `main`:

```bash
git switch -c agent/<disposable-branch-name>
```

## Task description

Write the Implementation Plan and Task in Japanese. Define goals, edge cases and the desired internal shape of the implementation.

## Tests

Follow `bun:test` for unit tests and Playwright-based `bun test:e2e` for end-to-end tests. Add tests first and commit them separately.

* Unit tests: run locally with `bun test`. They run in pre-commit and must pass before proceeding.
* E2E tests: run only on CI with `bun test:e2e`. Cover each major user flow with at least one E2E test. If an E2E fails in CI, analyze logs and fix unit/implementation as needed.

## Code and logging

Write code after tests. Follow `docs/LOGGING_GUIDELINES.md` and add sensible logs.

## Commit granularity

Make small commits per step. Examples:

* `test:` — add unit tests
* `feat:` / `fix:` — implementation steps
* `refactor:` — add or change logging
* `wip:` — experimental commits (see below)

Each commit should pass pre-commit (Biome + unit tests) unless intentionally using `--no-verify` for WIP.

## Running tests

* Unit: `bun test`
* E2E (CI): `bun test:e2e`
* All checks (CI): `bun run check-all`

## PR and CI automation

Push the agent branch, create a PR, wait for CI, and react to failures.

```bash
git push -u origin agent/<disposable-branch-name>

gh pr create \
  --base dev \
  --head agent/<disposable-branch-name> \
  --title "<task-name>" \
  --body "This PR was generated by agent."
```

Monitor CI and extract failure logs:

```bash
# wait for checks, non-zero exit on failure
if ! gh pr checks --watch; then
  gh run list --limit 1 --json databaseId,status,conclusion
  gh run view $(gh run list --limit 1 --json databaseId --jq '.[0].databaseId') --log-failed
  exit 1
fi
```

If CI fails, analyze logs, fix tests or implementation, repeat the cycle (write tests, code, push, PR).

## Merge and cleanup

When approved and merged, clean up locally:

```bash
git switch dev
git pull
git branch -d agent/<disposable-branch-name> || true
git fetch -p
```

Enable GitHub repository setting `Automatically delete head branches` so remote branches are removed on merge.

## WIP commits and pre-commit hooks

* Pre-commit runs Biome + unit tests only.
* Use `git commit --no-verify -m "wip: <description>"` for intermediate, failing states when you need history.
* Keep WIP commits clearly labeled and convert to proper commits before final PR.

Example commit flow

```bash
# add tests first
git add packages/runtime/src/components/For.test.ts
git commit -m "test(runtime): add unit tests for For component"

# implement in small steps
git add packages/runtime/src/components/For.ts
git commit -m "feat(runtime): add For component structure"

git add packages/runtime/src/components/For.ts
git commit -m "feat(runtime): implement list rendering in For component"

# intermediate failing state
git add packages/runtime/src/components/For.ts
git commit --no-verify -m "wip: implementing nested component handling"

# final fix
git add packages/runtime/src/components/For.ts
git commit -m "fix(runtime): resolve nested component issue"
```
